# Threadbear 固有の接続境界・契約・運用チェックリスト

設計（工程2）・実装（工程4）・反映（工程7）で必ず点検する Threadbear 固有の制約と境界。該当しない項目は理由付きで「非適用」とし、未点検のまま通過させない。

---

## 1. 再利用・適応の3層判定とUI統合

| 層 | 対象 | 基本方針 | 注意点 |
|---|---|---|---|
| **第1層: 直接再利用・抽出** | 純ロジック、パーサー、検索、座標・境界計算、テキスト切り詰め、プロンプト、応答パーサー、CSS/SVGデータ、元テスト | そのまま実行または最小限の接続アダプタで取り込む。書き直してエッジケース（UTF-16境界、ページング、重複整理、タイムゾーン等）を落とさない | `third_party/` や移植元manifestに固定SHA・Git blob・`LICENSE`/`NOTICE` を記録し一致確認する |
| **第2層: Webパネル統合** | 複雑なReact/HTML/CSS UI（フォーム、エディタ、カード、ピッカー等） | GPUIへ劣化書き直しする前に、既存のWebパネル等で原典部品＋CSSをそのまま動かせるか評価する | 汎用RPCや所有者トークンをWeb側へ渡さない。表示中対象限定の短命leaseを発行し、画面クローズ・切替時に即失効させる |
| **第3層: ネイティブ適応実装** | GPUI/Rust、Runner/TS、Convexへの書き起こし | 書き方はThreadbear流に適応するが、原典の操作順・入力体験（Enter/Esc/blur/複数行等）・ショートカット・失敗時の下書き保持・エッジケースを落とさない | CEFネイティブビューは通常GPUI要素を覆う等、描画レイヤー制約を実装前に検証し、安易な「上部固定バー」「二段階確認の追加」に逃げない |

- **既存資産の優先再利用**: Threadbear 既存の `ThreadStore`、CLI実行基盤、認証、Scheduler、下書き・画像添付、Project/Highlights、Thread移動（梱包・暗号化・復元）と重複する別台帳や別プロセスを作らない。
- **UI原則（`AGENTS.md` 準拠）**: すべての操作に楽観的更新または二重クリック防止スピナー、全コントロールへのtooltip、メインスレッド高負荷でも止まらないアニメーション、plain words な文言を守る。

## 2. 4経路パリティとプロトコル契約

Threadbear のスレッド・機能は **① 本Runner / ② 他Runner（Convex中継） / ③ iPhone / ④ Web** の4経路から到達する。

- **プロトコル先行**: `docs/protocol/` の該当ファイルを先に更新し、双方が未知フィールド・未知イベントに耐性を持つ設計にする。
- **パリティ登録**:
  - 新しいスレッド要求・操作 → `runner/src/parity.ts`
  - デスクトップが新しく描画する要素種別 → `runner/src/draw-parity.ts`
  - 表示（カード項目・メッセージ・完了カード等）の変更 → `runner/test/unit/scenarios.test.ts`
  - デスクトップ挙動変更 → `features/` の spec と対応ステップ（`features/verify-pairing.mjs` 整合）
  - transcript の折りたたみ変更 → `desktop/core/tests/golden`
- **ツール引数互換とコンテキスト予算**:
  - 既存の Threadbear ツール引数を変える場合、再開済みセッションが旧形式で呼び続けても壊れないよう旧引数を引き続き受理する。
  - エージェントへ常時渡すプロンプト・ツール定義を増やす場合は `runner/context-budget.json`（`context-budget.test.ts`）を確認する。
- **凍結領域の尊重**: 旧Swiftアプリ（`app/`、`dock/`）は原則凍結。デスクトップ変更は `desktop/`（GPUI）に入れる。
- **実験フラグ**: 試行段階の新機能は `docs/experiments.md` に従い `experimentOn` で保護し、既定オフ・明示オンの境界を明確にする。

## 3. 権限・セキュリティ・分離境界

- **所有者限定操作と権限表の整合**
  - 新しい RPC・Convex 公開関数を追加したら、権限表・CallerGate・Boxキー拒否テスト・プロトコル一覧を **同じ変更内で** 揃える（公開関数名と権限表の不一致で `tb land` が落ちる／認可漏れするのを防ぐ）。
- **端末・外部向け投影（Projection）での漏洩防止**
  - 所有者用の保存スキーマから `pick()` 等で一部を切り出すとき、未知フィールド保持（passthrough）を引き継いでローカルパスや内部設定がペアリング端末へ漏れないか必ず試験する。公開専用スキーマを一覧・保存・競合・再送の全経路に共通適用する。
- **Webパネル／CEF 連携の最小権限**
  - Web側には「現在表示中の対象ID＋許可フィールド限定＋画面クローズで失効」のleaseのみを渡し、別対象IDの指定・権限外項目・閉じた後の遅延リクエストを拒否する試験を書く。
  - 隔離テスト用のローカルHTTP fixtureを製品コードへ流用しない。
- **CEF サンドボックスと署名（macOS）**
  - 外部Webページを開く機能・CEF構成を変更する場合、`no_sandbox` のまま放置しない。同梱フレームワークの厳密署名と、レンダラープロセスがアプリ外ファイルを読めないこと（`sandbox_check` 等）を実アプリで検証する。
- **認証情報・私的データの保護**
  - OAuthトークン・Keychain・実セッションログ・実スレッドexportをGit・外部送信・テストfixtureに絶対に含めない。

## 4. Convex・永続化・後方互換

- **Convex 制約**
  - モジュール名にハイフンを使わない（例：`bot-foo.ts` は不可、`botFoo.ts` にする）。
  - APIバージョン番号を増やす場合、上流リリース取り込みとの競合や旧クライアント/旧Runnerの挙動を考慮する。
- **データ形式バージョンと旧版Runner保護**
  - 旧Runnerが意味を知らない新形式・新状態を導入するときは、書き込み前に新形式対応の supervisor / リリース稼働を確認し、ロック下で形式番号を上げる。旧版への rollback でデータが壊れない保護を入れる。
  - ローカル保存の読み書きでは、別項目を編集した際に将来用フィールド（未知項目）を誤って落とさないか確認し、逆に未知の不正プロバイダー値等は拒否する。
- **原子書き込み・再送冪等・復旧**
  - 永続ファイル更新は原子書き込み（atomic write）とロックを使う。
  - 破壊的操作や状態遷移（削除・移転・委任・予約実行等）は操作ID・revision・所有世代で冪等化し、応答消失や途中再起動でも二重実行・巻き戻りが起きないことを検証する。
  - 複数コピー（ローカル・同期先・移転元・管理バックアップ・端末下書き等）が存在するデータの削除・復元は、管理対象と管理外（会話履歴・外部バックアップ等）の境界を明示し、全管理境界の確認が揃うまで完了表示や破壊UIを公開しない。

## 5. 権利・出典・ライセンス管理

- 外部コード・語彙・アイコン・プロンプト・テストを取り込む前に、対象固定SHAの `LICENSE`・`NOTICE`・ファイルヘッダーを確認する。
- `third_party/` や `NOTICE`・manifest にリポジトリURL・固定SHA・対象パス・Git blob/ハッシュ・改変内容を記録し、原典との照合テストでドリフトを防ぐ。
- 配布物へのライセンス表示同梱が必要な場合は、計画の完了条件に含める。

## 6. Threadbear 開発・反映・資源運用

- **worktree 規律**
  - `main` チェックアウトや他スレッド使用中の worktree（`slot-*`）を触らない。
  - 外部フォルダから開始したスレッドは `./borrow-worktree.sh` で借り、すべて `main` へ着地して確認が終わってから `./borrow-worktree.sh --give-back <dir>` で返却する。
- **反映と自動更新**
  - 反映は worktree 内での `tb land`（または `runner/bin/tb land`）のみ。手動の `git merge` / `git push main` は禁止。
  - アプリ・Runner変更の着地後は、本番アプリや live runner を手動再起動せず `wait_for_app_restart` を使い、更新後に `build.json` のコミット・desktop tree・Git祖先関係を読み取り照合する。
  - 本番設定、live runner、実配備Convexを無断で変更しない。
- **実画面・重負荷・容量管理**
  - ユーザーの操作中Macで実ポインタや実キーボードを奪うテストを無断実行しない（隔離アプリ・自動化フック・明示許可された範囲に限定）。
  - Rust等の重いビルドは `scripts/one-build.sh` や既存キャッシュを再利用する。
  - 空き容量不足でガードに引っかかった場合は停止理由にせず、許可された範囲で終了済みの再生成可能な中間データだけを整理して空きを確保し、作業を続行する。
- **ドキュメント整合**
  - ユーザーが見える挙動を変えたら `docs/guide.md`、Mac上のファイル/タイマー/通信を変えたら `docs/on-your-mac.md`、フォーク固有要素は `docs/forking.md` を最新に保つ。
